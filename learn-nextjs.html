1 · What is Next.js? Foundation

Next.js is a React framework made by Vercel. React alone gives you UI components — Next.js adds routing, server-side rendering, API endpoints, fonts, and build optimisation on top, so you don't have to wire them all yourself.

React alone

Gives you components, state, and props. You must add a router, a build tool, and a server yourself.

Next.js on top

Adds file-based routing, server components, API routes, image optimisation, and Vercel deploys in one install.

Your version

Next.js 16.2.6 with React 19.2.4. Uses the new App Router (the modern approach, inside the app/ folder).

What Next.js replaced for you

Without Next.js you'd needNext.js provides
A separate Express or Fastify serverRoute Handlers in app/api/*/route.ts
React Router or TanStack RouterFile-based routing — a file is a route
Webpack / Vite configBuilt-in Turbopack (zero config)
Google Fonts <link> tagsnext/font/google — zero layout shift
Manual SSR setupServer Components render on the server automatically

5 · Server vs Client components Core Concept

This is the most important concept in modern Next.js. By default every component is a Server Component. Add "use client" at the top to opt into the browser.

Server ComponentClient Component
Where it runsNode.js server onlyBrowser (+ server on first load)
Can usefs, env vars, databases, async/await at top leveluseState, useEffect, onClick, localStorage, window
Cannot useuseState, useEffect, browser APIsfs, secrets, server-only packages
JS sent to browserNone — renders to HTMLYes — full component JS
Directive(none — default)"use client" at top of file

How it maps to your files

Server Components server

page.tsx, layout.tsx, Hero.tsx, About.tsx, Stack.tsx, Experience.tsx, Contact.tsx, Footer.tsx

No interactivity needed — just render HTML from content.ts data.

Client Components client

Nav.tsx, AIWidget.tsx, Projects.tsx, AnimInit.tsx, StatCounter.tsx

Need useState, useEffect, click handlers, or browser APIs (localStorage, IntersectionObserver).

// Nav.tsx — needs useState for theme toggle + menu state
"use client";       ← THIS LINE makes it a Client Component

import { useState, useEffect } from "react";

export default function Nav() {
  const [isDark, setIsDark] = useState(false);  ← browser state
  // ...
}
Common mistake — "use client" is contagious If a Server Component imports a Client Component, the client component becomes the "client boundary." Everything above it can still be a server component. Everything inside it must also be a client component (or have no server-only code).

6 · TypeScript basics Core Concept

TypeScript adds types to JavaScript. The browser never sees TypeScript — it gets compiled away. Types are only for your editor and build step (they catch bugs before you run the code).

// Plain JavaScript — no type safety
function greet(name) { return "Hello " + name; }
greet(42);  // no error — but "Hello 42" is probably wrong

// TypeScript — compiler catches the mistake
function greet(name: string) { return "Hello " + name; }
greet(42);  // ❌ Error: Argument of type 'number' is not assignable to type 'string'

7 · layout.tsx — the root shell Your Files

layout.tsx wraps every page on the site. It renders once per navigation — its state persists between page changes. Think of it as the permanent outer frame.

📄 app/layout.tsx
import type { Metadata } from "next";
import { Inter_Tight, JetBrains_Mono, Source_Serif_4 } from "next/font/google";
import "./globals.css";   ← imported once here, applies to everything

// next/font downloads the font subset at BUILD TIME
// and self-hosts it — zero layout shift, no Google CDN request at runtime
const interTight = Inter_Tight({
  subsets: ["latin"],
  weight:  ["400", "500", "600", "700", "800"],
  variable: "--font-inter-tight",  ← exposed as a CSS variable
});

// SEO metadata — shows in browser tab + search results
export const metadata: Metadata = {
  title:       "Mohamed Idris — Senior React Developer",
  description: "...",
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html
      lang="en"
      data-theme="light"               ← default theme attribute
      suppressHydrationWarning           ← suppress mismatch warning (theme changes server→client)
      className={`${interTight.variable} ${jetbrainsMono.variable} ${sourceSerif.variable}`}
    >
      <head>
        <script dangerouslySetInnerHTML={{
          __html: `(function(){
            var t = localStorage.getItem('v4-theme');
            if(t) document.documentElement.setAttribute('data-theme', t);
          })();`
          // ↑ runs INSTANTLY before first paint — prevents theme flash
        }}/>
      </head>
      <body>{children}</body>   ← page.tsx renders here
    </html>
  );
}
Why suppressHydrationWarning? The server renders data-theme="light". But the browser's inline script immediately changes it to "dark" if the user prefers dark mode. React would normally warn "server and client HTML don't match." suppressHydrationWarning tells React to ignore this mismatch on the <html> element — because we intentionally changed it.

Long strings in ABOUT.paragraphs and EXPERIENCE[].bullets use **double asterisks** to mark bold text — just like Markdown.

// In content.ts:

// renderBullet.tsx processes this:
export function renderBullet(text: string) {
  return text.split(/(\*\*[^*]+\*\*)/).map((part, i) =>
    part.startsWith("**")
      ? <strong key={i}>{part.slice(2, -2)}</strong>
      : <Fragment key={i}>{part}</Fragment>
  );
}

10 · Every component explained Your Files

Nav.tsx client

📄 app/components/Nav.tsx

Manages two pieces of state: isDark (theme) and menuOpen (mobile hamburger). The theme toggle writes to localStorage and sets data-theme on <html> directly — the CSS custom properties react instantly.

function toggleTheme() {
  const next = isDark ? "light" : "dark";
  document.documentElement.setAttribute("data-theme", next);  ← all CSS vars switch
  localStorage.setItem("v4-theme", next);                     ← persists across visits
  setIsDark(!isDark);                                           ← re-renders icon
}

The mobile menu CSS specificity fix: .mobile-menu a has specificity 0,1,1 which overrode .mobile-cta at 0,1,0. Fixed with .mobile-menu .mobile-cta — two class selectors = 0,2,0.

Hero.tsx server

📄 app/components/Hero.tsx

The landing section. Imports HERO from content.ts, renders animated stat counters via <StatCounter>, and includes an <AIWidget> with no projectContext prop (global mode).

StatCounter.tsx client

📄 app/components/StatCounter.tsx

Uses IntersectionObserver to detect when the number is scrolled into view, then animates from 0 to the target with a cubic ease-out. Uses requestAnimationFrame for smooth 60fps animation.

const tick = (now: number) => {
  const progress = Math.min((now - start) / duration, 1);
  const eased = 1 - Math.pow(1 - progress, 3);  ← cubic ease-out
  setDisplay(Math.round(eased * value * 10) / 10);
  if (progress < 1) requestAnimationFrame(tick);
};

AnimInit.tsx client

📄 app/components/AnimInit.tsx

Renders nothing visible. Its only job: set up an IntersectionObserver on every .reveal element in the DOM. When an element enters the viewport, it adds the .in class which triggers the CSS fade-up animation.

const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        entry.target.classList.add("in");    ← triggers CSS animation
        observer.unobserve(entry.target);  ← only animate once
      }
    });
  },
  { threshold: 0.08, rootMargin: "0px 0px -32px 0px" }
  //                   ↑ trigger 32px before the element reaches the edge
);

Projects.tsx client

📄 app/components/Projects.tsx

Tracks openId — the ID of the currently expanded project. When a project card is clicked, it toggles open/closed. A useEffect watches openId and auto-scrolls to the AI widget using a double requestAnimationFrame.

// Double rAF trick — why?
// rAF 1: React's state update has been committed to the DOM
// rAF 2: The browser has painted the new layout (project detail panel is visible)
// Then scrollIntoView can measure the element's actual position
const id = requestAnimationFrame(() =>
  requestAnimationFrame(() => {
    const widget = document.querySelector<HTMLElement>(".proj-detail .ai-widget");
    if (widget) widget.scrollIntoView({ behavior: "smooth", block: "nearest" });
  })
);

AIWidget.tsx client

📄 app/components/AIWidget.tsx

The interactive chat component. Used twice: once in Hero.tsx (no projectContext prop), and once per expanded project in Projects.tsx (passes projectContext so the AI knows which project is being discussed).

All instances share the same token budget via localStorage — usage in the hero widget counts against the same daily limit as usage in the project widget.

11 · api/ask/route.ts — the AI endpoint Your Files

This is a server-only file. It's a mini Express-like handler that receives a POST request, validates the request, checks rate limits, calls the Groq AI, and returns a JSON response.

📄 app/api/ask/route.ts
  • 1
    Receive the request

    Browser sends POST /api/ask with JSON body { question, context, deviceId }.

  • 2
    Check the API key

    If GROQ_API_KEY is missing or still a placeholder → return 503 Service Unavailable with a helpful message.

  • 3
    Build the rate-limit key

    Combines deviceId (from localStorage) and the client's IP address into a string like "abc123:192.168.1.1". This makes it hard to bypass by just clearing localStorage or using a VPN.

  • 4
    Check the server-side usage map

    An in-memory Map stores { tokens, resetAt } per key. If over limit → 429 Too Many Requests.

  • 5
    Build the system prompt

    Reads data/resume.txt and data/about-me.txt from disk. Appends them to the system prompt so the AI knows Mohamed's background. Ignores files that still contain the template placeholder text.

  • 6
    Call Groq API

    Sends the user's question + context + system prompt to LLaMA 3.3-70b. Max 200 output tokens. Returns the answer + token count used.

  • 7
    Update usage & respond

    Increments the server-side token counter. Returns { answer, tokensUsed, serverTokensUsed, tokenLimit }.

// The in-memory Map — lives as long as the server process
const serverUsage = new Map<string, { tokens: number; resetAt: number }>();

// Reading files from disk (server-side only — never from a browser)
function readData(file: string): string {
  try { return readFileSync(join(process.cwd(), "data", file), "utf-8").trim(); }
  catch { return ""; }  ← fails silently if file missing
}
In-memory Map resets on server restart This is fine for a portfolio — it means rate limits reset whenever Vercel redeploys (which is rare). For a production app with real security requirements you'd use Redis or a database instead.

12 · lib/ utilities Your Files

lib/usage.ts browser only

📄 app/lib/usage.ts

Manages the token budget on the client side using localStorage. This is what shows the usage meter in the UI. It stores a JSON object:

{
  deviceId:   "a3f8-...",      ← stable UUID, identifies this browser
  tokensUsed: 350,             ← accumulated token usage today
  limit:      2000,            ← from AI_TOKEN_LIMIT in content.ts
  resetAt:    1748123456789    ← Unix ms timestamp 24h from first use
}

Key design: all three AIWidget instances on the page call readUsage() and addTokens() which read/write the same localStorage key — so the 2000 token limit is shared, not per-widget.

lib/renderBullet.tsx shared

📄 app/lib/renderBullet.tsx

A pure utility function. Takes a string with **bold** markers, splits it on the regex pattern, and returns an array of React elements (mix of plain text and <strong> tags).

// Output: ["He led ", <strong>3 engineers</strong>, " at Comcast"]

// With    (): ["He led ", "**3 engineers**", " at Comcast"]  ← we can transform it

13 · AI system design System Design

The AI feature spans four layers: browser UI, server route, rate-limit store, and external AI API. Here's the full picture.

LAYER 1 — Browser
AIWidget.tsx
User types question → reads localStorage for deviceId + usage → sends POST /api/ask
lib/usage.ts
localStorage "portfolio_ai_v1" — tracks tokensUsed, resets after 24h. Shared by ALL widget instances.
Usage meter UI
Progress bar + "350 / 2000 tokens" shown below each chat form. Updated after every response.
↓ POST /api/ask {question, context, deviceId}
LAYER 2 — Next.js Server
app/api/ask/route.ts
Validates request, reads env var GROQ_API_KEY, extracts IP from headers.
serverUsage Map
In-memory rate limit. Key = deviceId:IP. Prevents server-side bypass even if localStorage is cleared.
data/ files
Reads resume.txt + about-me.txt via fs.readFileSync. Injected into system prompt. Never exposed to browser.
↓ POST to Groq API {model, messages, max_tokens: 200}
LAYER 3 — Groq Cloud
LLaMA 3.3-70b-versatile
Free-tier LLM. Receives system prompt (bio + resume + about-me) + user question. Returns answer in ≤200 tokens.
System prompt
"You are Mohamed Idris speaking in first person. Answer in ≤90 words, confident, no bullet lists, no invented metrics."
↑ {answer, tokensUsed, serverTokensUsed, tokenLimit}
LAYER 4 — Back to browser
AIWidget receives response
Calls addTokens(data.tokensUsed) → updates localStorage → re-renders usage meter → patches message in conversation.

15 · Animations — two systems System Design

System 1 — Hero entrance (CSS keyframes, runs once on page load)

/* globals.css — plays automatically when the element renders */
@keyframes fadeUp {
  from { opacity: 0; transform: translateY(14px); }
  to   { opacity: 1; transform: translateY(0); }
}

.hero-meta  { animation: fadeUp 0.55s  0.05s  var(--ease) both; }
.display    { animation: fadeUp 0.65s  0.12s  var(--ease) both; }  ← h1
.hero-lede  { animation: fadeUp 0.55s  0.22s  var(--ease) both; }
.hero-cta-row { animation: fadeUp 0.5s 0.32s  var(--ease) both; }
//                                 ↑ stagger: each element starts 0.1s later

System 2 — Scroll reveal (IntersectionObserver, triggers on scroll)

/* Base state — invisible, shifted down */
.reveal {
  opacity: 0;
  transform: translateY(18px);
  transition: opacity 0.5s var(--ease), transform 0.5s var(--ease);
}

/* AnimInit.tsx adds ".in" when element enters viewport */
.reveal.in {
  opacity: 1;
  transform: translateY(0);
}

/* Delay variants — stagger siblings in a group */
.reveal-d1 { transition-delay: 0.05s; }
.reveal-d2 { transition-delay: 0.15s; }
.reveal-d3 { transition-delay: 0.25s; }
.reveal-d4 { transition-delay: 0.35s; }
Why two separate systems? The hero plays immediately — the user should see it right away. Everything else should animate as the user scrolls to it — that's what makes the page feel alive as you explore it. Using keyframes for one and IntersectionObserver for the other keeps each system focused on its job.
